What should you inspect?

Change layout before reducing readability.

Prefer wrapping, width, line breaks and stacking. Avoid fixed-height text containers and clipping.

Use Mono for aligned technical quantities, identifiers and tolerances—not arbitrary figures or decorative pseudo-engineering labels.

04.04 / DECISION RULESDerived from Notion baseline + web application studies

Display versus Sans

Choose Display for concise brand statements only. Use Sans for longer, descriptive headings and service explanations. Never simulate Archivo width via horizontal transforms.

Length before size

If a title overflows, first review wording, max-width, line break and column layout. Do not reflexively shrink important content to fit a fixed box.

Responsive reading

Preserve meaningful hierarchy under narrow layouts and browser zoom. Allow text blocks and controls to grow vertically; maintain full access to essential copy.

Technical credibility

Apply Mono to comparative specifications and part identifiers, not as superficial engineering decoration. Keep ordinary numbers in Sans when part of prose.

02 / COMPOSITION ANATOMY

Then, explain the structure.

A grid is a system of relations between a page, its regions, its modules and the content inside them. These are not interchangeable units.

GEOMETRY
DIAGRAM / CONCEPT
INDEX / ANNOTATION
READING REGION
LOCAL MODULE A
LOCAL MODULE B
Page / canvas

Define content width, safe outer margins and the relationship to site navigation. The site shell is not automatically the same grid as a composition's inner content.

Region / boundary

Reserve index and content territories only where the information architecture benefits from them. A specimen can use a shared anchor without demanding a left rail in every future design.

Module / nested grid

Build parallel columns, technical records and other local structures inside their assigned parent region. Lines and surfaces should have deliberate boundaries, rather than crossing unrelated territory.

Vertical rhythm

Choose typographic leading and spacing units as related reference systems. Optical corrections remain legitimate. A displayed baseline guide is a diagnostic, not proof that glyphs have been optically aligned.

Allowed exceptions

Images, colored fields, marks, interaction affordances and motion may establish or break alignment purposefully. Document the reason and preserve reading order; do not let typography prescribe the entire expression system.

01

IBM
Design Language
& Carbon

IBM 2x Grid ↗Carbon Overview ↗Carbon Usage ↗

Geometry as a coherent hierarchy of decisions.

Documented method. IBM's 2x Grid uses repeated divisions by two to construct a flexible geometry. Its 8px mini unit is a reference for web and product dimensions, spacing, margins and padding. For typographic work, a baseline unit can derive from line leading or a fraction of it; IBM also describes combining this with the mini unit. These are complementary methods rather than a demand that every visible measurement be identical.

Carbon distinguishes fluid, fixed and hybrid layouts. Editorial experiences may benefit from fluid columns; fixed-size tiles can wrap according to available space; hybrid structures combine the two. Carbon also distinguishes editorial, product/documentation and high-density page models: a page's purpose influences the grid. A 16-column large-screen structure is central to its 2x approach, while 12-column / three-part arrangements can be supported in particular existing systems. Do not label 12 columns an IBM default.

Gutters are relationships, not just a CSS gap. In Carbon's usage model, wide (32px), narrow (16px) and condensed (1px) describe different component and container behaviors. In narrow mode the container may extend into a gutter while its text remains on the underlying column reference. Labeled form controls require additional care. Nested grids inherit a parent's boundaries; a child grid should not reset the page geometry arbitrarily.

Composition matters more than technical compliance. Carbon explicitly observes that an accurately gridded layout can still lack hierarchy, and warns that excessive module repetition without whitespace becomes monotonous. Content and user goal precede selection of columns and modules.

Geniotek interpretation / candidate

Use Page → Region → Module → Content as an implementation hierarchy. Begin with the reading task (editorial, service narrative, dense lookup), then select an appropriate content width and nested structure. Treat 12/16 columns, 8px units and gutter values as tested candidates, not frozen design tokens.

Agent check: Can every meaningful text start be traced to its parent region? Are the table rule and background extension intentional? Does a visually correct grid still communicate priority?

02

Apple
Human Interface
Guidelines

HIG Layout ↗Design Principles ↗

Design the relationship a reader perceives.

Documented method. Apple's Layout guidance emphasizes familiar relationships between content and controls, a hierarchy grounded in reading order, and deliberate alignment. Aligning items suggests association; indentation suggests subordination. Negative space, containers and separating rules can express groups, but not every group needs all three.

Progressive disclosure limits the number of competing choices shown at once. In this chapter, that means presenting a composed result before revealing guides, configuration options or diagnostic details. A design tool should reveal its complexity as the reader needs it, rather than making controls the primary subject.

Adaptability is structural. Apple asks designers to account for changing window sizes, orientation, localization and text length, and larger text sizes. Parallel sections may need to stack, rows may grow, and media may require different cropping or scale. A fixed 390px viewport inside a scrolling desktop panel is a comparison aid, not sufficient evidence that a real mobile page behaves correctly.

Apple does not prescribe a universal 12- or 16-column web grid for Geniotek. These principles provide interaction, relationship and reflow criteria, not borrowed pixel tokens.

Geniotek interpretation / candidate

For every pattern, state the user's first reading target, the secondary content, the expected scanning direction, and what changes at a narrower width. Keep an explanatory note visually subordinate to the subject it explains; leave room for genuine content to carry the hierarchy.

Agent check: Can the user find the main message without opening the inspector? Do spacing and indentation accurately describe relationships? Do 200% zoom, longer translations and stacked mobile content preserve meaning and controls?

Proportion and quiet order, derived from the material.

Documented project intention — EUC (2017). The academic identity serves a multidisciplinary audience covering urban landscape, planning, architecture, ecology and public life. Its designers describe using scale and grid as representations of planning and the city, with signs and information unfolding through proportional multiples. Their stated intention is to diminish conspicuous design intervention while retaining precision, accessibility, pattern and order.

Documented project intention — SNAPSHOT (2017). This bilingual investigative interview book contains a large volume of information. ABCD explicitly describes its design task as organizing that material logically, orderly and neutrally. It is therefore a more relevant reference for our editorial reading pattern than generic minimalist layouts. The source supports the information objective; it does not publish the complete construction measurements needed to reproduce its spreads.

Geniotek inference, not an ABCD rule. Start with the semantic structure and actual text density. Establish a limited set of shared origins and proportional relations. Use carefully judged whitespace and visual grey to distinguish the main reading rhythm from supporting annotation. Let differences in content create compositional variation instead of introducing unrelated oversized type, arbitrary shifts or dark blocks.

ABCD does not publish a Geniotek-ready 12-column CSS grid, gutter preset, universal typography scale or mandatory left-rail pattern through these cases. None should be attributed to them. Project images and further portfolio material are research references, not direct component specifications.

Geniotek interpretation / candidate

Review the page with all grid overlays off. Ask whether it feels precise without looking technical for its own sake. Compare the relationship between content blocks, not merely their coordinate values. The composition must remain legible and purposeful even when its hidden geometry is never shown.

Agent check: Is a title large because the content warrants emphasis, or because the layout needs spectacle? Does the negative space articulate meaning? Are all labels necessary? Does the design remain balanced across text densities?

AGENT OPERATING
INSTRUCTIONS

Before generating a page

  1. Identify the reading task, content importance and user action. Do not begin by selecting a column count.
  2. Choose the page model: open editorial, structured service, reference/technical or another justified form.
  3. Establish the page boundary and region anchors; place local grids inside them. Define where lines, surfaces and media may extend.
  4. Choose text measures, spacing and relative visual weights. Type, color, symbols, icons, interaction and motion can all participate; none are subordinate to Typography alone.
  5. Build an actual responsive composition, then evaluate at narrow widths, longer text, 200% zoom and with guides turned off.
  6. Run geometry checks. Record intentional deviations and distinguish measurable alignment from human visual judgment.

Not yet approved: 12 / 16 columns, 24px gutters, 8px spacing for Geniotek, and any universal index rail. Use them only as experiment configurations until confirmed against real pages.

IBM DESIGN LANGUAGE
CARBON

Color infrastructure is a hierarchy of roles.

Documented IBM / Carbon approach. Color systems distinguish brand identities from functional UI responsibilities. Carbon's themes and tokens give stable semantic names to different contexts: background, layer, field, border, text, link, icon, focus and support states. Values can change with theme while the role remains stable. Different nested surfaces may require different background and border tokens.

Color helps orient readers but cannot replace information hierarchy. Excessive container coloring can make everything compete. A component with correct tokens may still feel busy or fail to explain what matters. Interactive focus, hover and disabled behavior must be assessed separately from a static marketing composition.

Geniotek application. Preserve the established brand violet. Use the deeper action violet as a contrast-sensitive candidate. Maintain quiet neutral reading planes and reserve functional support colors for their actual meanings; never paint an entire service journey as success, caution or failure without supporting data.

AGENT CHECK

State the job of each color: identity, text, surface, action, support status, data relation or expressive concept. Do not copy IBM's entire palette or number of tokens. Test the value in its intended surface and interaction state before publishing.

GENIOTEK / EXECUTION
FOR AGENTS

Decide what color must achieve before coding.

  1. Identify the task: brand statement, engineering evidence, service explanation or technical reference.
  2. Choose expressive intensity: low for dense references, medium for service information, high for selected brand moments—not as a rigid page classification.
  3. Verify actual data and copy first. If a tolerance range is specified, calculate its endpoints; do not invent measured distributions, yields or test outcomes.
  4. Map roles before HEX values: brand, action, text, surface, status, evidence. Check the foreground/background combination.
  5. Select an accepted compositional direction only when relevant: Visible / Invisible, tolerance band, Service A Color Field or Service B Open Editorial.
  6. Preserve the accepted Typography and Grid constraints without forcing every block into the same left-index pattern.
  7. Test longer copy, small-screen reflow, readable contrast, keyboard focus and non-color labels. Avoid tiny colored state lights as the only cue.
  8. State what is still unapproved: supporting neutrals, semantic state palette, dark-theme requirement, color area ratios and gradient behavior.
OUT OF SCOPE FOR THIS PHASE

No dependence on confidential product photos or AI imagery. No compulsory purple/black split screen, no five-color traffic-light workflow, no fake manufacturing outcomes. Gradients remain deferred to a separate research phase.
