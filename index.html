RESEARCH NOTES

What should you inspect?

Does the title preserve a readable phrase? Does it overwhelm the supporting copy? Can the layout reflow without clipping? Are you evaluating genuine font characteristics or a fallback? These values are an experimental comparison, not an approved token.

03.01 / RESPONSIVE BEHAVIORFixed baseline · practical tests

Recompose.
Don’t just shrink.

Apple’s semantic type and adaptivity principles suggest testing how content and its surroundings behave together. Web equivalents are browser zoom, fluid containers, wrap and reflow—not SwiftUI APIs.

FROZEN RULE

Keep the complete message.

Do not shrink key text just to fit a rigid box. Let containers grow; allow natural line breaks and reflow. Required actions and essential details must not disappear when enlarged.

REVIEW THE RESULT

Stress cases to verify.

Short vs long headline, technical punctuation, language fallback, mobile width, 200% browser zoom and loading failure. The zoom option here is a visual simulation; real browser zoom must still be tested.

03.02 / CONTEXTUAL DECISIONSFrom general advice to explicit criteria
DISPLAY OR SANS?

Choose by message length.

Short, intentional brand claims may justify Display; long functional titles should remain Sans. Check actual Archivo width axis before approving Display.

FONT SIZE OR CONTAINER?

Change layout before reducing readability.

Prefer wrapping, width, line breaks and stacking. Avoid fixed-height text containers and clipping.

DATA OR DECORATION?

Mono must carry information.

Use Mono for aligned technical quantities, identifiers and tolerances—not arbitrary figures or decorative pseudo-engineering labels.

04.04 / DECISION RULESDerived from Notion baseline + web application studies

Display versus Sans

Choose Display for concise brand statements only. Use Sans for longer, descriptive headings and service explanations. Never simulate Archivo width via horizontal transforms.

Length before size

If a title overflows, first review wording, max-width, line break and column layout. Do not reflexively shrink important content to fit a fixed box.

Responsive reading

Preserve meaningful hierarchy under narrow layouts and browser zoom. Allow text blocks and controls to grow vertically; maintain full access to essential copy.

Technical credibility

Apply Mono to comparative specifications and part identifiers, not as superficial engineering decoration. Keep ordinary numbers in Sans when part of prose.
