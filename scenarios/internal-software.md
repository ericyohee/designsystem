# 内部软件

先读 [品牌底座](../core/brand.md)。

**这份文件目前是框架。** 下面的栏目是这个场景将来要有的内容；标着“待定”的栏目还没有规则，做到这个场景时再逐项确定。待定的栏目不要自己补成规则：按“直接沿用”的部分做，并把你做的选择列出来给负责人确认。

## 直接沿用

- 颜色和字体：[tokens.md](../core/tokens.md)。网页技术栈可直接引入 [`core/tokens.css`](../core/tokens.css)。
- 界面文字用 Sans；表格里的数值、编号用 Mono。
- 可点击的元素用 `action`。`brand` 只用于品牌识别（如标志旁、启动页），不用于普通按钮。
- 橙色 `result` 只用于成绩和结果，不用作警告或报错的颜色。
- 状态提示必须同时有文字，不能只靠颜色。

## 规范框架

| 栏目 | 要定的内容 | 状态 |
| --- | --- | --- |
| 1. 适用范围 | 哪些软件算内部软件，给谁用，品牌感要多强 | 待定 |
| 2. 技术路线 | 自己做界面零件，还是选一套现成的再换上我们的颜色和字体 | 待定，见下方“待决定” |
| 3. 标志与产品名 | 标志放在哪、多大，各个软件怎么命名 | 待定，依赖 [品牌底座](../core/brand.md) 的标志规则 |
| 4. 颜色 | 背景、文字、分隔线、可点击元素各用哪个颜色 | 数值沿用底座；界面里的分配待定 |
| 5. 状态颜色 | 成功、警告、错误、提示各用什么颜色 | 待定。橙色已有职责（成绩、结果），警告色需要另定 |
| 6. 字体与字号 | 界面里的字号档位 | 字体分工沿用底座；字号待定 |
| 7. 间距、圆角与疏密 | 元素之间留多少空，角有多圆，一屏放多少信息 | 待定 |
| 8. 界面零件 | 按钮、输入框、表格、弹窗、导航等的样子和用法 | 待定 |
| 9. 图标 | 用哪一套图标，大小和粗细 | 待定 |
| 10. 特殊状态 | 没有数据、加载中、出错时显示什么 | 待定 |
| 11. 深色模式 | 要不要做，做的话颜色怎么对应 | 待定 |
| 12. 易用性 | 键盘操作、放大后是否可用、文字是否够清晰 | 文字清晰度沿用底座；其余待定 |
| 13. 示例 | 做对的例子和常见错误的例子 | 待定 |
| 14. 交付前检查 | 发出去之前逐条核对的清单 | 待定 |

## 待决定

内部软件需要大量通用界面零件，不适合从零做。可以选一套现成的开源组件库，再用上面的颜色和字体换肤。Meta 的 [Astryx](https://astryx.atmeta.com/) 支持这种做法，但它目前是测试版，且要求 React 19。是否采用尚未决定。
